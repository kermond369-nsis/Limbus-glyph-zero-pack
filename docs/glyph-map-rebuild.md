# glyph_map 提取与重建说明（2026-09-21）

本表不是手写，也不是直接拷贝：**从社区安卓/iOS 汉化成品的行为中提取，再用本仓工具重建**。
本文记录提取方法、关键规则与验证结果，供以后零协更新时复现/增量维护。

## 1. 参照对象

| 对象 | 用途 |
|------|------|
| 零协 `LimbusLocalize_2026090501`（LLC_zh-CN，2048 JSON） | 源文本 |
| `ghcruise/LimbusCompany-IOS-Localization` release `v1.114.0-alpha` 的 `localize_jp.zip`（2187 JSON） | 替换行为参照（该项目的替换工作声明 "文本替换了所有汉字至日语字形"） |
| `pzwboy/LocalizeLimbusCompanyForAndroid` | 同上（ghcruise 的 Android 转发布，行为一致） |

## 2. 提取方法（差分法）

对每个共同文件、每个 JSON 字符串路径（`dataList[i].field`）：

1. **两边同时剥离游戏富文本标签**（`<color=#..>`、`<style="..">`、`</..>` 等白名单正则），避免标签差异干扰；
2. 等长字符串 → 逐字符统计转移 `(src → tgt)`（含"保持不变"计数）；
3. 不等长字符串 → `difflib` 对齐，replace 块等长则拆为字符对，不等长且 ≤8 字符则记为**词组候选**；
4. 过滤：
   - 仅保留 **CJK 源** 的单字映射（剔除拉丁/数字等噪声；全角标点白名单如 `《》→「」`、`；→;` 除外）；
   - 每字取主目标；要求替换覆盖率 ≥ 90%（占该字全部观察）且（≥10% 占比 或 ≥10 次绝对量）；
5. 词组候选按频次人工复核后进入多字规则。

提取统计（2026-09-21）：等长观察 131,444 对、转移源字 4,572 个、得单字映射 1418 条、词组规则 8 条。

## 3. 闭环验证（可复现）

| 检查 | 结果 |
|------|------|
| 产物 vs 参照（剥离标签，逐串比较，2047 共同文件） | 匹配率 **99.17%**（233,796/235,754；余下 1,958 为源文本版本差异：数字、句子更新、行序变化） |
| 产物字符 ⊆ `safe_charset`（非 ASCII、非 Hangul） | **0** 越界 |
| 产物 JSON 有效性（2048 文件全部重解析） | **0** 失败 |
| 高频字样例（你→袮、吧→叭、吗→麼 等 100% 覆盖） | ✅ |

残差核查：1,958 个 mismatch 均为"参照基于更新版零协文本"所致（例：`1層↔2層`、`15区↔25区`、人名/句子改写），不是替换逻辑差异。
唯一例外已另行处理：`喂`（感叹词语境 `喂，喂→喟，喟!`、动词 `喂它→澆灌它`，其余 425 处保留，与参照一致）。

## 4. 语言/字符豁免规则

- **Hangul（韩文）**：游戏原生语言为韩语，JP 槽字体链必然覆盖韩文；闭环校验豁免。
- **Cyrillic（西里尔）**：`Девять`（"九"协会）→ 词组规则替换为 `九`（与参照一致）。
- **ASCII**：JSON 语法/英文文本，天然可显示；闭环校验豁免。
- **富文本标签**：照零协原文保留（`<i>`/`<style=...>`/`<color=...>`/`<noparse>` 等，与参照方案使用同一套标签体系）。
  - 参照方案在部分文本额外注入了大量关键词高亮（`<color=#...>` ×10 万），本仓**未复刻**该增强（属渲染层附加，非字形替换必需）。

## 5. 与旧版（full5）的差异

| 方面 | 旧 full5 | 新 full7 |
|------|----------|----------|
| 生成方式 | 手工反推 + 补漏（"啊"占位 249 条） | 差分法提取 + 规则过滤 |
| "啊"占位 | 249 条 | 0 |
| 条目覆盖 | 1417 条（含 13 条疑似笔记多字） | 1418 单字 + 8 词组（全部有来源） |
| 闭环校验 | 无 | 打包时 fail-fast（safe_charset） |
| 三副本 | pack/App×2 漂移 272 条 | 本仓唯一来源（App 侧待同步） |

## 6. 复现步骤（留给未来的维护者）

```bash
# 1) 取零协原文与参照成品（各自最新）
#    零协: https://github.com/LocalizeLimbusCompany/LocalizeLimbusCompany/releases
#    参照: https://github.com/ghcruise/LimbusCompany-IOS-Localization/releases（localize_jp.zip）
# 2) 差分（见本文件 §2 方法；工作脚本位于开发方工作区 glyph-rebuild/）
# 3) 生成 glyph_map.json / safe_charset.txt
# 4) python3 scripts/audit_glyph_map.py --corpus <语料>   # 必须 AUDIT OK
# 5) python3 scripts/pack_zero_to_jp.py --input <语料> --output jp.zip \
#      --glyph-map assets/glyph_map.json --safe-charset assets/safe_charset.txt
```

> 注：`safe_charset.txt` 为参照成品（剥离标签）字符全集（4612 字符）。
> 零协更新后若出现"outside safe charset"告警，说明新文本含新字符：按 §4 规则分类处理，
> 需要"确认真实可显示"的，把字符（附依据）补入该文件。
